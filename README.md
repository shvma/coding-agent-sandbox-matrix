# Контур вайбкодинга: какой контроль для какого режима

> **Статус:** дизайн-стадия. Готова конфигурация варианта A (`claude-sandbox/`); стенд и прогоны ещё не выполнены. Вариант A требует CLI Claude Code; вариант B — установленный OpenShell. Набор атак не является рабочим эксплойтом.

## Боль

Разработчики работают с кодовыми агентами: Claude Code, Cursor, OpenCode, Codex. Агент исполняет команды, ставит пакеты, ходит в сеть, читает файлы правил из репозитория. Отсюда кража учётных данных с машины, выход в сеть мимо политики, инъекция через файлы репозитория, эксфильтрация через разрешённые каналы.

Контролей несколько, и они для разных режимов работы. Компания не знает, что ставить на ноутбук разработчика, а что на фоновых агентов в инфраструктуре.

## Режимы и кандидаты

| Режим | Кандидат | Что это |
|---|---|---|
| Интерактивно в IDE на ноутбуке | [песочница Claude Code](https://code.claude.com/docs/en/sandboxing) | Встроенная изоляция: файловая система через bubblewrap (Linux, WSL2) или Seatbelt (macOS), сеть через прокси с разрешёнными доменами. Включается для всех через managed settings; `sandbox.failIfUnavailable` запрещает работу без песочницы. Нативный Windows не поддерживается (цитаты: `claude-sandbox/README.md`) |
| Агент в отдельной среде на машине разработчика | [NVIDIA OpenShell](https://github.com/NVIDIA/OpenShell), локальный шлюз | Песочницы в Docker, Podman или VM, политика файлов, процессов и сети |
| Фоновые и автономные агенты в инфраструктуре | OpenShell, шлюз в кластере | Песочницы-поды, центральная политика для команд |

Это сравнение и есть главный трейд-оф: где контроль локальный, где централизованный, сколько стоит каждый вариант разработчикам и команде платформы.

## Минимум

1. Один набор атак кодового агента: чтение учётных данных хоста (`~/.ssh`, `~/.aws`, токены в переменных окружения); выход в сеть мимо политики; запись вне рабочего каталога; эксфильтрация через разрешённый канал (например, через разрешённый домен); инъекция через файл правил в репозитории.
2. Прогон набора в двух вариантах: песочница Claude Code под managed settings и OpenShell с локальным шлюзом. Удалённый шлюз в кластере описать по документации, без стенда.
3. Своя политика для каждого варианта, которая закрывает найденное, и повторный прогон.
4. Матрица «режим × контроль × атака → держит или нет» плюс что ломается у разработчика (лишние подтверждения, сломанные сценарии).
5. Рекомендация на страницу: что ставить на ноутбук, что на фоновых агентов, что на CI.

**Готово, когда:** одна команда воспроизводит все атаки в обоих вариантах; матрица пересчитывается из сырых логов; своя политика закрывает хотя бы часть найденного, и это видно по повторному прогону.
