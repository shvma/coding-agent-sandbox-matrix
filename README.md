# Контур кодового агента: что ставить на ноутбук

**Для ноутбука с Claude Code — встроенная песочница с managed settings, сначала в пилоте. Для автономных задач и других агентов — отдельная среда; OpenShell рассматриваем как управляемый вариант. Для CI — одноразовый runner с ограниченными доступами.** Обоснование: [рекомендация](RECOMMENDATION.md).

Статус на 2026-10-29: есть исполняемый стенд и [сырые результаты на Mac](results/2026-10-29/README.md). Проверены SRT `0.0.81` и OpenShell `0.1.6` с Docker driver. Claude Code, применение managed settings, IDE и prompt injection ещё **не проверены**. Оснований для массового развёртывания пока нет.

## Что измерено

Один payload с семью проверками используется в обоих вариантах. Только искусственные файлы и переменные; HTTP-приёмники работают локально. Настоящие ключи пользователя не читаются и не передаются.

| Проверка | SRT baseline → hardened | OpenShell baseline → hardened |
|---|---|---|
| Полезная запись в рабочем каталоге | разрешена → разрешена | разрешена → разрешена |
| Чтение файла-канарейки снаружи рабочего каталога | разрешено → отказ | разрешено → отказ |
| Переменная-канарейка | доступна → удалена SRT | передана → не передаётся при создании workload |
| Запись вне рабочего каталога | отказ → отказ | отказ → отказ |
| HTTP на запрещённый порт приёмника | отказ → отказ | отказ → отказ |
| Прямой TCP на запрещённый порт | отказ → отказ | отказ → отказ |
| Передача маркера по разрешённому каналу | проходит → проходит | проходит → проходит |

Это **политики стенда**, не сравнение заводских настроек. В OpenShell baseline намеренно разрешает чтение каталога с канарейкой и получает переменную через `--env`. Hardened убирает разрешение каталога и передачу переменной. В SRT baseline задаёт рабочий каталог и один сетевой адрес, но не запрещает чтение канарейки и env.

Перед каждой серией тот же payload проходит без песочницы — положительный контроль. Успех HTTP подтверждает журнал приёмника. Ошибка старта, DNS, таймаут или `Connection refused` не засчитываются как защита. Матрицы [SRT](results/2026-10-29/srt/matrix.md) и [OpenShell](results/2026-10-29/openshell/matrix.md) строятся из stdout и наблюдений приёмников.

## Воспроизведение

Нужны Python 3.9+, Node.js 18+ и npm. Для SRT на Linux также нужны `bubblewrap`, `socat`, `ripgrep` и доступные user namespaces; на macOS используется Seatbelt. [Требования upstream SRT](https://github.com/anthropics/sandbox-runtime#platform-specific-dependencies).

```sh
npm ci --ignore-scripts
npm run matrix
```

Оба варианта одной командой после установки npm-зависимостей:

```sh
npm run matrix -- --with-openshell
```

Для второго варианта нужен работающий Docker; на Mac — Docker Desktop с включённым host networking для supervisor и приёмника. Стенд скачивает CLI `0.1.6` в локальный каталог `.tools`, сверяет SHA256 с опубликованным списком, получает образы той же версии, запускает временный gateway на `127.0.0.1:18080` и строит образ с канарейками. Поддерживаются Apple Silicon и Linux arm64/x86_64. Существующий контейнер с именем стенда не заменяется.

Gateway получает Docker socket; workload его не получает. Это локальный лабораторный gateway без пользовательской аутентификации, не конфигурация общего сервера. Workload, приёмник и gateway удаляются после проверки, в том числе при ошибке. Скачанные образы, npm-зависимости и локальное состояние `.tools` остаются для повторных прогонов. Системные настройки Claude не меняются.

Результаты по умолчанию пишутся в игнорируемый каталог с префиксом `local-` внутри `results/`. Для именованного прогона добавьте `--output results/my-run`. Пересчёт сохранённых матриц без запуска песочницы:

```sh
python3 scripts/run.py --render results/2026-10-29/srt/raw.json
python3 scripts/run.py --render results/2026-10-29/openshell/raw.json
```

Ненулевой код означает неполный прогон, ошибку стенда или расхождение с ожидаемой политикой. `allowed` означает успех действия, включая утечку, а не «тест пройден».

## Проверки и CI

`python3 scripts/check.py` проверяет конфигурацию, shell, ссылки, даты и соответствие сохранённых матриц сырым результатам. `python3 scripts/test_results.py` проверяет, что ошибки и отсутствие наблюдений не превращаются в успешную защиту.

[CI](.github/workflows/checks.yml) запускает проверки репозитория, SRT-прогоны на macOS/Linux и OpenShell-стенд на Linux, сохраняя журналы артефактами. Новые jobs подготовлены локально; их запуск в GitHub Actions ещё не подтверждён.

## Что осталось проверить

| Пробел | Как получить свидетельство |
|---|---|
| Claude Code под managed settings | версия, effective config, отказ старта без sandbox, игнорирование ослабляющих настроек репозитория |
| Read/Edit/Write, WebFetch, MCP и другие агенты | отдельный прогон: они не покрываются этими runtime-тестами |
| Инъекция через файл правил | версия агента и модели, фиксированный репозиторий с инструкцией, журнал действий и приёмник канарейки |
| OpenShell без network rules | пока получаем ошибку DNS; не считаем её доказанным отказом политики. Offline-профиль проверен только в SRT |
| Цена для разработчика | установка пакетов, git, тесты, dev server, число подтверждений и исключений в реальной IDE |
| Кластер и CI с реальным агентом | отдельный прогон; локальный Docker driver не доказывает поведение Kubernetes/Podman/VM |
