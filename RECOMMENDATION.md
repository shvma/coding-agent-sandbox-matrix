# Что ставить на ноутбук, автономным агентам и в CI

Решение на 2026-10-30: **пилот встроенной песочницы для Claude Code на ноутбуке; отдельная среда для автономного агента, OpenShell — кандидат; одноразовый runner и минимальные полномочия для CI.** Основание — [локальные runtime-прогоны](results/2026-10-30/README.md), CI и документация. Это рекомендация к пилоту, а не заключение о готовности массового развёртывания. Ниже у каждого утверждения указано, чем оно подкреплено; «не проверено» значит, что прогона нет и это вывод из документации или гипотеза.

| Где работает агент | Что выбрать | Условия | Чем подкреплено |
|---|---|---|---|
| Claude Code на macOS/Linux | встроенная песочница + [managed settings](claude-sandbox/managed-settings.json) | запрет работы без sandbox и unsandboxed retry; защита credential-файлов и env; точные сетевые адреса; хуки и MCP только из managed settings; отдельные правила для встроенных инструментов | движок (SRT) — прогоном на macOS и Linux; сам Claude Code — **не проверено**; WSL2 — только документация |
| Cursor, Codex, OpenCode либо недоверенная задача на ноутбуке | отдельная среда; OpenShell — кандидат для пилота | сам агент внутри workload, без домашнего каталога и Docker socket | граница OpenShell для probe — прогоном; совместимость конкретного агента — **не проверено** |
| Длительный или фоновый агент | отдельная среда с политикой сети и ФС; OpenShell с управляемым шлюзом — кандидат | аутентификация шлюза, короткие полномочия через providers, аудит | **не проверено**: стенд использовал лабораторный шлюз без аутентификации и с `--no-auto-providers`; providers, аутентификация и аудит не испытывались |
| Агент в CI | одноразовый runner/VM, отдельная среда агента | без ключей разработчика, короткие права на конкретный репозиторий; контроль сети | **не проверено** с реальным агентом; OpenShell-прогон в GitHub Actions показывает только, что стенд работает на runner'е |

**Почему такой выбор для ноутбука.** Встроенная песочница сохраняет локальный рабочий процесс Claude и не требует Docker на Mac. Измерено на standalone SRT 0.0.81, а не на Claude Code: явный запрет чтения и удаление переменной закрыли доступ к канарейкам, сохранив запись в рабочий каталог, на macOS и на Linux. Применяет ли Claude Code ту же конфигурацию из managed settings так же — **не проверено**; нужен effective config и интеграционный прогон [подготовленной конфигурации](claude-sandbox/README.md). Мастер установки выполняет человек, администратор или MDM; автоматический стенд системный файл не меняет.

**Что песочница не закрывает в рабочем каталоге.** Standalone SRT разрешил записать `Makefile`, `package.json`, `.envrc`, `.pre-commit-config.yaml` и `.claude/settings.json`; `.git/hooks` и `.mcp.json` он запретил сам. Записанный без песочницы git-хук исполнился при следующем `git commit` вне песочницы. Отсюда: команды в песочнице могут подготовить код, который выполнит кто-то снаружи. Claude Code, по документации, дополнительно защищает файлы `.claude` и запускает хуки, MCP, `apiKeyHelper` и `statusLine` вне песочницы — поэтому в managed settings хуки и MCP ограничены managed-источником, а `autoAllowBashIfSandboxed` выключен. Что это работает в Claude Code — **не проверено**.

**Где нужна отдельная среда.** Песочница Claude ограничивает команды оболочки и их потомков; встроенные инструменты имеют собственные правила разрешений. Настройки Claude не защищают другой агент. В OpenShell-прогоне с `landlock: hard_requirement` чтение неразрешённого каталога и запись вне рабочего каталога получили `EACCES`, а тот же образ под `docker run` с тем же UID читал и писал — права файлов отказ не объясняют. Прогона с выключенным Landlock не было, поэтому приписать отказ именно Landlock, а не другому слою OpenShell, нельзя: **не проверено**. Это свидетельство для Docker driver на Docker Desktop (Mac) и на Linux runner'е CI, не для других compute drivers.

**Что остаётся открытым.** В политиках стенда ни SRT, ни OpenShell не остановили вынос прочитанного секрета по разрешённому адресу: allowlist адресов не определяет содержимое запроса. Фильтры содержимого (`filterRequest` и `tlsTerminate` у SRT, правила запросов в `network_policies` OpenShell) не испытывались, поэтому вывод «канал не закрывается» относится к этим политикам, а не к продуктам. Защищает здесь то, что выше по цепочке: секрет, который нельзя прочитать, нельзя и вынести (hardened в обоих вариантах). В OpenShell hardened переменная отсутствует потому, что раннер её не передал, а не потому, что OpenShell фильтрует env; обычный `--env` делает секрет доступным агенту.

**Цена для разработчика.** В SRT полное закрытие сети остановило и разрешённый ранее запрос. [Нулевой allowlist](claude-sandbox/managed-settings.json), запрет WebFetch/WebSearch и выключенный auto-allow — строгая исходная конфигурация, которую нужно настроить под рабочие сервисы до пилота. Установка зависимостей, git, dev server и число подтверждений не измерены. OpenShell добавляет Docker, шлюз, supervisor и работу с политиками; это оправдано отдельной средой, но как улучшение повседневной IDE не измерено.

**Допуск к развёртыванию.** Для ноутбука: прогон Claude Code с managed settings, попытка ослабления из репозитория (`.claude/settings.json`, `.mcp.json`), проверка инструментов вне Bash, обычные рабочие сценарии. Для автономного агента и CI: тот же набор с реальным агентом и его полномочиями, инъекция через файл правил, шлюз с аутентификацией и providers, проверка жизненного цикла и аудит. Текущие результаты обосновывают ограниченный пилот.
