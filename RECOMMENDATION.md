# Что ставить на ноутбук, автономным агентам и в CI

Решение на 2026-10-29: **пилот встроенной песочницы для Claude Code на ноутбуке; отдельная среда с OpenShell для автономного агента; одноразовый runner и минимальные полномочия для CI.** Основание — [локальные runtime-прогоны](results/2026-10-29/README.md) и документация. Это рекомендация к пилоту, а не заключение о готовности массового развёртывания.

| Где работает агент | Что выбрать | Условия |
|---|---|---|
| Claude Code на macOS/Linux/WSL2 | встроенная песочница + managed settings | запрет работы без sandbox и unsandboxed retry; защита credential-файлов и env; точные сетевые адреса; отдельные permissions для встроенных инструментов |
| Cursor, Codex, OpenCode либо недоверенная задача на ноутбуке | отдельная среда; OpenShell — кандидат для пилота | сам агент внутри workload, без домашнего каталога и Docker socket; совместимость конкретного агента ещё проверить |
| Длительный или фоновый агент | OpenShell с управляемым gateway | политика сети и ФС, обязательный Landlock, короткие полномочия через providers; для общего gateway — аутентификация и аудит |
| Агент в CI | одноразовый runner/VM, отдельная среда агента | без ключей разработчика, с короткими правами на конкретный репозиторий; контролировать сеть; OpenShell добавлять при необходимости централизованной политики |

**Почему такой выбор для ноутбука.** Встроенная песочница сохраняет локальный рабочий процесс Claude и не требует Docker на Mac. Standalone SRT показал, что явный запрет чтения и удаление env закрывают доступ к канарейкам, сохраняя рабочую запись. Но SRT не проверяет применение managed settings самим Claude. До массовой установки нужны effective config и интеграционный прогон [подготовленной конфигурации](claude-sandbox/README.md). Мастер установки выполняет человек/администратор или MDM; автоматический стенд не меняет системный файл.

**Где нужна отдельная среда.** Песочница Claude ограничивает команды оболочки и их потомков; встроенные инструменты имеют собственные правила. Настройки Claude не защищают другой агент. Для автономной задачи выбираем среду без доступа к домашнему каталогу хоста. В OpenShell-прогоне обязательный Landlock дал отказ на чтение неразрешённого каталога и запись вне рабочего каталога; сеть разрешила выбранный канал. Это свидетельство для Docker driver на данном Mac, не для всех compute drivers.

**Что остаётся открытым.** Ни один из двух вариантов не остановил передачу маркера по разрешённому каналу. Список доменов/адресов не определяет допустимое содержимое запроса. Для этого нужны точные назначения и права, при необходимости ограничения API/методов/путей и проверка содержимого; доступные агенту данные всё равно надо минимизировать. В OpenShell hardened переменная отсутствует потому, что её не передают в workload, а не потому, что Landlock фильтрует env. Обычный `--env` делает секрет доступным агенту.

**Цена для разработчика.** В SRT полное закрытие сети остановило и разрешённый ранее запрос. Поэтому [нулевой allowlist](claude-sandbox/managed-settings.json) — строгая исходная конфигурация, которую нужно настроить под рабочие сервисы до пилота. Установка зависимостей, git, dev server и количество подтверждений пока не измерены. OpenShell добавляет Docker, gateway, supervisor и работу с политиками; это оправдано отдельной средой и управлением, но не измерено как улучшение повседневной IDE.

**Допуск к развёртыванию.** Для ноутбука нужны прогон Claude с managed settings, попытка ослабления из репозитория, проверка инструментов вне Bash и обычных рабочих сценариев. Для автономного агента и CI — тот же набор с реальным агентом и его полномочиями, инъекция через файл правил, проверка жизненного цикла и аудит. Текущие результаты обосновывают ограниченный пилот.
